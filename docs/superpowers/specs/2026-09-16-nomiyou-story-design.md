# 노미요 게임 스토리 디자인 (진행 중 초안)

> 상태: **DRAFT / 브레인스토밍 + 1차 코드 구현 병행 중**. 이전 세션이 저장 없이 종료된 적이 있어, 대화/코드 유실을 막기 위해 계속 체크포인트로 커밋한다. 다른 PC에서 이어서 작업할 경우 이 문서 맨 아래 "다른 PC에서 재개하는 방법"부터 읽을 것.

## 지금까지 확정된 결정 사항

- **복구 범위**: 이전 세션 스토리 내용은 기억나지 않음 → 처음부터 새로 브레인스토밍.
- **톤**: 귀여움 → 공포 반전 (평소엔 힐링/일상 스트리머 컨셉, 특정 트리거로 분위기가 뒤집히며 진짜 정체/비밀이 드러나는 반전형 공포).
- **핵심 미스터리 축**: 파닥이들의 정체/운명.
- **파닥이 정체**: 과거 시청자/구독자가 갇힌 존재. 노미요의 방송을 좋아하다 돌아가지 못하고 파닥이로 변해버림.
- **노미요의 인지**: 전혀 모름, 본인도 피해자. 플레이어와 함께 진실을 파헤치는 구조. 다만 "방=자신의 공간이라 파닥이들이 그나마 안전함"이라는 인과관계는 논리적으로는 몰라도 희미하게 눈치채고 있음(막연한 책임감/애정).
- **가해자/원인**: 특정 인물이 아니라 숨은 **'구독' 계약** — 시스템/저주 그 자체. "구독하기"라는 행위 자체에 걸린 규칙이 사람들을 가둠.
- **방 vs 숲의 의미**: 방(집) = 시청자에게 보여지는 안전한 '방송부스'. 숲(밤의 숲) = 구독자들이 실제로 갇혀 있는 진짜 공간. 방↔숲 전환(문)이 "방송 온/오프"의 경계와 대응.
- **권속 내 권한 차등**: 방과 숲은 둘 다 기본적으로 시스템의 권속이지만, 방은 스트리머 노미요 본인의 공간이라 시스템이 노미요에게 조금 더 권한을 허용함 → 방 안의 파닥이들이 숲의 존재들보다 좀 더 편하게 지낼 수 있음. 방/숲의 차이는 "감시 여부"가 아니라 "허용된 권한의 정도" 스펙트럼.
- **고성(중첩 게임)과 숲의 관계 (확정)**: 같은 공간의 다른 가면 — 시스템이 진짜 숲을 시청자용으로 각색해 "고성 탈출 게임"으로 보여줌.
- **숲의 괴물 정체 (확정)**: 오염이 극한까지 치달은 파닥이의 최종 형태.
- **엔딩 구조 (확정, 이전 "하이브리드 A안"의 부분 해방/톤 가변 아이디어를 대체함)**:
  - 진엔딩/배드엔딩을 가르는 축은 오직 **"노미요가 구독자(파닥이)를 놓아주느냐 vs 붙잡느냐"**. 노미요의 방송 지속 여부는 이 분기와 무관.
  - 메커니즘: 숲 끝 탈출 직전, 노미요(=플레이어)에게 명시적인 갈림길 대화 선택지가 주어짐 ("놓아준다" / "붙잡는다"류).
  - **진엔딩**: 구독자들이 시스템의 구속에서 완전히 벗어나 현실로 돌아가고, 이후 현실에서 자유의지로 노미요의 방송을 다시 응원하게 됨 — "저주로 묶인 가짜 소속"에서 "현실의 자발적 팬심"으로 정상화. 연출: 엔딩 이후 방 안 CHAT 칠판에 현실로 풀려난 (구)구독자들의 응원 메시지가 표시됨.
  - **배드엔딩**: 붙잡혀 떠나지 못한 파닥이들이 그 즉시 오염이 극한까지 치달아 괴물로 변신, 끔찍한 비명을 지르며 끝남 — "붙잡았기 때문에 결국 다 잃는다"는 아이러니. (열린 질문: 노미요가 괴물 정체를 아는 시점이 변신 순간인지, 그 전에 미리 아는지는 미확정 — 미리 알고도 매달리는 쪽이 비극성이 커서 유력.)

## 확정된 장면/연출 비트

- **중반 복선 장면**: 방 안에 있을 때 방문을 쾅쾅 두드리는 소리 → 창문으로 확인하면 시꺼멓고 커다랗고 눈이 붉은 괴물이 문밖에 있음 (이 시점엔 정체 모름). 파닥이1: "밖에 괴물이 있어." 파닥이2: "요즘 자꾸 저게 나타나. 숲에서도 본 적 있어. 무서워." — 파닥이들이 이미 알고 무서워하고 있었다는 복선.
- **괴물 조우 = 게임오버**: 숲 탐험 중 괴물에게 붙잡히면 — 노미요가 잡히면 괴물이 깨진 글자(글리치)로 말을 걸고 노미요가 "뭐라고?" 되묻다 죽음. 동행 파닥이가 잡히면 물어뜯겨 몸이 반토막 나서 죽음(더 직접적/잔인한 연출로 대비).
- **배드엔딩 직전 공포 연출**: 방송 중 괴물이 찾아와 방문을 쉴 새 없이 두드리고("쾅쾅쾅쾅") 그 틈으로 작게 "보내줘 보내줘 보내줘" 소리가 들림 — 괴물이 되어버린 뒤에도 파편적으로 "놓아달라"는 의사가 남은 처참한 연출. 방송 중이라 시청자에게도 들려서 채팅에 "지금 그거 무슨 소리예요?" 질문이 올라오고, 노미요는 "모르겠어요 하하"로 얼버무림 — 진짜 공포가 코앞인데도 스트리머의 가면(명랑함)을 반사적으로 유지하는 지점이 반전형 공포 톤의 핵심 장면.

## 열린 질문 (다음에 확정 필요)

1. **밴 이벤트 상세**: 오염된 여러 파닥이가 고성 게임 속에 돌아가며 나타났다 시스템에 의해 사라지는 반복 현상으로 확정됨(특정 한 명이 아님). 다만 정확한 트리거/빈도, 노미요가 다가갔을 때의 구체적 소멸 연출은 미정.
2. **고성의 구체적 모습**: 성 이름/분위기/방 구성, 왜 "고성" 스킨인지.
3. **오염 3단계의 정확한 트리거**: 정상 힌트 → 이상한 이야기 → 글자 뭉개짐, 이 진행을 무엇이 유발하는지(시간? 구독 유지 기간? 특정 행동?).
4. **정상 힌트 vs 메타 힌트 배치 원칙**: 고성 곳곳에 몇 개, 어디에 배치할지.
5. **파닥이 개별 캐릭터**: 최소 2~3명의 이름/성격/"과거 어떤 구독자였는지" 사연.
6. **노미요가 괴물 정체를 아는 시점**: 변신 순간 vs 미리 알고 있었는지 확정 필요.
7. **문 두드리는 괴물과 숲의 괴물의 관계**: 동일 개체인지, 파닥이마다 각자의 괴물이 있는지.
8. **오프닝/도입부**: 게임이 어떻게 시작되는지.
9. **진엔딩 에필로그 디테일**: CHAT에 뜨는 응원 메시지 실제 예시.
10. **시스템(구독 저주)을 얼마나 명시적으로 설명할지**: 끝까지 신비하게 둘 부분 vs 명확히 설명할 부분의 경계.

## 구현 진행 상황 (1차 코드 슬라이스: 데스크 상호작용 + 채팅/구독 루프)

스토리를 말로만 계속 다듬기보다 "게임을 만들어서 테스트해가며 디테일을 잡고 싶다"는 요청에 따라 코드 구현으로 전환함. 상세 구현 계획(파일별 변경 내역, 설계 근거)은 `superpowers:brainstorming`/`Plan` 에이전트가 작성한 계획 문서를 기반으로 하며, 요약은 아래와 같다. **전체 계획 원문은 세션 로컬 플랜 파일(`~/.claude/plans/shimmying-wobbling-wren.md`, 이 저장소 밖에 있어 다른 PC에는 없음)에 있었으므로, 재현 가능하도록 핵심을 여기 남긴다.**

### 요구사항
1. 플레이어(노미요)가 방의 데스크로 걸어가 상호작용(`KeyC`)하면 "방송 중" 상태 진입 (고성 미니게임 자체는 범위 밖).
2. 방송 중에는 채팅 로그 오버레이가 떠서 시청자 채팅이 스크롤됨 (시뮬레이션, 서버 없음).
3. 주기적으로 "OOO님이 1개월 구독을 시작했습니다" 이벤트 → 노미요 "감사합니다" 반응(말풍선) → 파닥이 실시간 생성.
4. 구독자 채팅에는 이름 옆에 🐤 배지 (이후 채팅에도 계속 유지).
5. 데스크에서 멀어지거나 `KeyC` 재입력 시 방송 종료. 생성된 파닥이는 방에 남음(숲↔방 전환에도 유지).

**2차 슬라이스 (2026-09-19): 파닥이 대화 + 날짜 + 점프스케어 + 게임 화면 + 창문**
- 파닥이 근처에서 `E · 말 걸기` 안내 → `E`로 대사(머리 위 말풍선, 자동 줄바꿈). 대사는 `src/systems/chickDialogue.js`에서 날짜별 3단계: 1~2일 따뜻한 잡담("안녕.", "오늘 날씨가 좋아.", "오늘은 방송 몇시야?"), 3~4일 불안("요즘 숲에서 자꾸 이상한 소리가 들려."), 5일~ 무서운 목격담("나 어제 숲에서 이상한 걸 봤어...", "그게 여기까지 쫓아오면 어떡하지?"). 6일~ 30% 확률로 점프스케어 "보내줘보내줘 보내줘!!!!!!"(크고 붉은 흔들린 글자 + 화면 흔들림 + 붉은 플래시 + WebAudio 효과음, `src/systems/scare.js`). 스케어 직후 다시 말을 걸면 아무렇지 않게 "오늘 게임 재미있었어." 같은 평범한 말. 공포 모드에서는 날짜와 무관하게 무서운 대사/스케어.
- **날짜**: 게임 접속(방송)을 한 번 끝낼 때마다 `DAY n` +1 (우상단 배지). 디버그 `?day=N`, `?talk=1`(첫 파닥이와 바로 대화), `?cam=x,y,z`.
- **게임 화면**: `E`로 앉으면 앉는 모션 후 화면이 검게 전환되고 `src/ui/gameScreen.js` 오버레이("고성 탈출" 성 실루엣 플레이스홀더 + LIVE 바 + 채팅창)로 바뀜. 접속 중엔 이동 키 무시, `E`로 종료(페이드 후 방으로 복귀, 일어남). 구독 반응 "감사합니다!"는 게임 화면 하단 상태 줄에도 표시. 미니게임 본체는 이후 이 오버레이 자리를 대체.
- **창문**: 방 앞벽(+z, 기본 카메라가 바라보는 쪽)에 숲이 보이는 창. 창밖 풍경은 벽 뒤 작은 밤 디오라마(무조명 실루엣 나무 + 달 하늘)이며 **스텐실 버퍼**로 창 구멍을 통해서만 그려져 카메라가 방 밖으로 나가도 풍경 상자가 화면을 덮지 않음 (`WebGLRenderer({ stencil: true })`).
- 의자 높이: 앉을 때 여우 루트를 좌석면보다 0.45 낮춰 몸통이 쿠션에 닿게 수정. 채팅 구독자 배지는 🐤 이모지 대신 파닥이 모양 인라인 SVG.

## 다른 PC에서 재개하는 방법

1. `git pull` 로 이 문서(및 지금까지의 코드 변경분)를 받는다.
